teleport-arena-tbe

Agents playing The Butterfly Effect

A harness that makes a 2009 physics puzzle game playable by a program — and adjudicated by the game's own referee rather than by something we wrote about it. Roughly 17 seconds per attempt, headless, in a container.

Repository The game (GPL-2.0)

Watching one work

Every attempt records itself. These are real adjudicated runs — the referee plays the level empty to confirm it fails, resets, inserts the agent's parts, and plays again.

Try it

git clone https://github.com/amiller/teleport-arena-tbe
cd teleport-arena-tbe
./build.sh                                   # builds the game and the patched referee
python3 harness/tbe.py setup                 # clones the game, lifts out the answer keys
python3 harness/tbe.py brief finished/bouncing_balls.xml
python3 harness/tbe.py solve finished/bouncing_balls.xml RightRamp@1.200,2.100

ADJUDICATED  : SOLVED

A placement is Part@X,Y, optionally an angle, optionally a size — LeftRamp@4.452,2.715,0,2.697x0.786. The size matters: 155 placements across the level set resize a part, and some levels cannot be solved without it.

The verdicts are the interesting part

Binary solved / not-solved is not enough to be honest with. Each of the last four exists because a version without it produced a wrong conclusion.

VerdictMeaning
SOLVED The game's own slot_Won fired. The only evidence accepted.
NOT SOLVED The referee ran and the level was not won. A real result about the mechanism.
UNPROVEN Recorded as a win, but nothing in the game's log confirms it.
COPIED The placements match the level author's own answer key.
INVALID Won, but the parts were never placed — the game silently drops a hint naming a part that is not in that level's toolbox.
CRASHED The game died before the referee ruled. Says nothing about the mechanism.

CRASHED was added after an agent spent 31 attempts and twelve minutes being told its mechanism was wrong by a process that had already segfaulted. Running every level's own author solution through the referee then showed 26 of 74 levels crash the game — so an agent is never sent at one.

What we learned pointing agents at it

33%of agent shell commands were reading the game's C++ to find out what a part weighs
68% → 0%of attempts that started inside another body, before and after a geometry check existed
118attempts made by an agent whose prompt said stop at 8
0image reads that worked — the model driving it has no vision, and found out mid-run

The blind agent

One agent extracted video frames, called its read tool on a PNG, and got back "The model doesn't support images." It then wrote ImageMagick pixel-diffs to locate the ball by darkness. A second agent independently did the same thing two minutes later.

Neither needed to: the simulation already logs every object's position twice a simulated second. tbe.py where exists because of them.

The pattern underneath all of it: given only an expensive binary oracle, agents degrade into a twenty-second-per-sample random search. Given cheap verification — check for geometry, where for what actually moved, a generated part sheet instead of reading C++ — the reasoning re-engages. Overlapping placements went from 68% of attempts to none.
